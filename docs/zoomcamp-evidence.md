# Zoomcamp project evidence audit

This audit follows the [official final-project brief](https://github.com/DataTalksClub/ai-dev-tools-zoomcamp/blob/main/project/README.md). Each row names inspectable evidence and its practical limit. RunGuard is a **local-only** application: the normal web/API/worker services remain stopped at the owner's request, there is no public URL, and public deployment/CD are deferred in [issue #34](https://github.com/AutoDotAI/RunGuard/issues/34). The owner's historical SQLite data was [backed up and imported offline into local PostgreSQL](https://github.com/AutoDotAI/RunGuard/issues/53#issuecomment-6431280726); the original SQLite volume and private backup remain available as recovery sources.

## Reviewer path and external work

Use the [README command index](../README.md) and [local reviewer guide](reviewer-guide.md) for the exact tested install, test, start, inspect, and stop sequence. `make test-postgres` requires a disposable PostgreSQL URL; CI provides one automatically. The [QA evidence index](reviewer-evidence.md) links issue-specific checks and CI runs. The normal site was stopped at the owner's request; this audit does not start it. The [offline import record](https://github.com/AutoDotAI/RunGuard/issues/53#issuecomment-6431280726) reports independent read-only verification, while the retained SQLite volume and private backup remain the recovery sources. Do not regenerate the signing secret when starting the imported application.

No screenshot is committed or counted as evidence. A reviewer may capture a redacted local screen after deliberately starting the application; a screenshot must not contain credentials, personal page text, or tokens. [Issue #63](https://github.com/AutoDotAI/RunGuard/issues/63) remains an **owner action**: the owner must evaluate three *other participants' projects* through the course platform. Agent QA on RunGuard and reviews received on RunGuard do not satisfy that requirement.
